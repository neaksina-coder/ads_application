Security

Last updated: May 25, 2026

Authentication and authorization

Google Ads account access is based on OAuth authorization. Neak Sina Ads Manager does not collect Google account passwords. API actions are limited to accounts and permissions authorized by the user.

Credential handling

Access tokens, refresh tokens, client secrets, developer tokens, and related credentials are treated as confidential. Production credentials are stored outside public source code and are accessible only to authorized operators.

Google Ads API Credential Security

The Google Ads API developer token is stored only in backend server environment variables. It is never included in frontend code, JavaScript bundles, browser cookies, or API responses sent to the client. OAuth refresh tokens are encrypted using AES-256 before storage. Access tokens are held in memory on the server only and are never persisted or sent to the browser.

Data protection

The platform uses HTTPS, role-based administrative access, audit logs, limited data retention, and operational monitoring to reduce risk to user and advertising data.

Rate Limiting and Abuse Prevention

The platform enforces per-user and per-account rate limits on Google Ads API calls. Retry logic uses exponential backoff and does not attempt repeated mutations that could create duplicate campaign objects. Unusual API activity triggers automated alerts.

User control

Users can request removal of connected accounts and data. Users can also revoke OAuth access directly through their Google Account permissions page.
